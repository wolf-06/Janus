# Janus — S2 Spec: the CODE_BUG fix loop

Source of truth: `PLAN.md` §1.3 and §4 (S2), implemented via
`docs/IMPLEMENTATION_PLAN.md` §2 **Phases 5–7**. This spec is the contract for milestone
**S2**. It describes only what is implemented; anything planned but not built is called out
as deferred.

S2 picks up where S1 stops. S1 produces a `CODE_BUG` diagnosis; S2 tries to turn that
diagnosis into a proven, source-only fix and surface it as a comment or a draft pull
request. The loop never merges, never force-pushes, and never claims a result it did not
measure.

**Status: implemented (Phases 5–7).** The pieces are `janus/core/localize/**`,
`janus/core/retrieve/git_grep.py`, `janus/core/generate/**`, `janus/core/prove/**`,
`janus/report/pr.py`, `janus/github/push.py`,
`GitHubClient.create_pull_request`, and the fix half of `janus/jobs/processor.py`.

---

## 1. Scope

**In scope:**

- Only a **`CODE_BUG`** decision enters the loop. `FLAKY`, `ENV` and `UNSURE` are
  comment-only and never localize, generate or prove a fix.
- **Localize** the fault with SBFL over per-test coverage.
- **Retrieve** similar past commits by grepping `git log -p`.
- **Generate** a minimal, source-only unified diff with an LLM.
- **Prove** the diff with four measured gates and a static policy gate, retrying with gate
  feedback.
- **Surface** the outcome in the repository's configured mode: **suggest** (default) or a
  **draft PR** in `pr` mode.

**Non-goals:** no auto-merge, no force-push, no test edits, no vector database, no benchmark
harness (Phase 8), no `git bisect` execution (deferred), and nothing in `PLAN.md` §3.

---

## 2. Pipeline position

`SandboxProcessor` runs the fix loop **inside the source checkout's context**, in the same
blocking thread as reproduction, because localization, retrieval, applying the diff and the
gates all need the checkout on disk. The outcome travels back on `_PipelineResult.fix`; the
async half persists it and posts the surface.

```
CODE_BUG decision
  → coverage run + parse (per-test contexts)
  → localize (SBFL)                       → suspects
  → retrieve (git log -p grep)            → prior fixes
  → read suspect sources
  → build prompt → LLM → extract diff
  → static policy gate
  → copy checkout → git apply
  → four measured gates
  → retry (≤ max_fix_attempts) with gate feedback
  → proven | gates_failed | rejected | no_diff | no_llm | no_localization | error
```

The loop never raises: any unexpected exception becomes an `error` outcome.

## 3. Localize

### 3.1 SBFL over per-test coverage

`janus/core/localize/sbfl.py` implements `localize(contexts, failing_test_ids, *,
formula=SbflFormula.OCHIAI, max_suspects=5)`.

- Input is one `CoverageContext` **per test** from the Python adapter's
  `--cov-context=test` run. File-level coverage cannot recover `ef` (failing tests that
  cover a line) or `ep` (passing tests that do), so it is not accepted.
- A context whose `test_id` is in `failing_test_ids` is failing; every other context is
  passing. Failing ids come from the CI targets plus the rerun attempts.
- For each `(file, line)`: `ef` / `ep` are the failing / passing test counts, and
  `nf` / `np` are the failing / passing test totals minus coverage.
- **Ochiai** is the default: `ef / sqrt((ef + nf) * (ef + ep))`. **DStar** (`*` = 2) is
  available as `SbflFormula.DSTAR`. Degenerate denominators score `0.0` and never raise.
- A line with **`ef == 0`** is covered only by passing tests and is **not a suspect**, so it
  is omitted even when its formula score would be defined.
- Duplicate contexts for the same test and repeated `(file, line)` pairs count once.
- Ranking is descending score, ties by `file` then `line`; the result is capped at
  `max_suspects` (default 5). Empty input, or failing ids absent from the contexts, yields
  `[]`.

### 3.2 Bisect (deferred, pure planner only)

`janus/core/localize/bisect.py` is a **pure planner and parser**, not an executor.
`plan_bisect` returns the ordered argv (`start`, `bad`, `good`, `run`, `reset`);
`parse_bisect_output` recognises `"<sha> is the first bad commit"` and counts progress
lines; `available(source_depth)` refuses depth `None` or `1`, because the source provider
fetches `--depth 1`. `Settings.bisect_enabled` defaults to `false`, and nothing in the fix
loop runs bisect. `suspects.introducing_commit` therefore stays `NULL` until a history-aware
checkout exists (D-070).

## 4. Retrieve

`janus/core/retrieve/git_grep.py` retrieves similar past fixes from the repository's own
history. There is no vector index and no embedding model (D-072).

- `build_terms(failing_tests=..., suspect_files=..., error_lines=...)` produces a small,
  de-duplicated, ordered term set (default limit 8): test names first, then suspect
  basenames, then the most distinctive tokens from the first error lines. Timestamps,
  absolute paths, line numbers, addresses and commit-like hashes are dropped as noise.
- `git_log_argv(terms)` returns a **shell-free** argv: `git log --oneline -p
  --max-count=50 -G<term>` per term. No terms means `()` and no retrieval.
- `parse_git_log` turns the output into `PriorFix` rows (`sha`, `subject`, `files`,
  bounded `diff_excerpt`); merge commits without a diff are kept, malformed input yields
  `[]`.
- `rank` scores each commit by the number of **distinct** terms it mentions; the processor
  keeps the top five and passes the top three into the prompt.

Retrieval is best-effort: a non-zero git exit or a subprocess failure logs and returns no
prior fixes, never fails the job.

## 5. Generate

### 5.1 Prompt

`janus/core/generate/prompt.py::build_fix_prompt` assembles, in order: the diagnosis, the
failing tests and bounded error excerpts, the ranked suspects, the relevant source (bounded
per file), at most three prior fixes, and the hard rules. It is capped at
`MAX_PROMPT_CHARS` (24,000). When the prompt is too long, **source gives way first** and
the rules are never truncated. The rules require exactly one unified diff, source files
only, no test or CI edits, and no failure suppression.

`extract_diff` accepts a fenced `diff`/`patch` block or a bare unified diff and returns
`None` for prose, so a non-diff reply cannot enter the proof loop.

### 5.2 LLM client

`janus/core/generate/llm.py` defines the tiny `LLMClient` protocol and two
implementations:

- `NullLLM` — `available = False`, returns `""`.
- `OpenAICompatibleClient` — one `POST {base_url}/chat/completions` with
  `temperature=0.0` and the configured `max_tokens`. The API key is sent only as a
  `Bearer` header; it is never put in the URL, never logged, and never echoed in an error
  (D-073).
- `build_llm(settings)` returns the real client only when **both** `llm_api_key` and
  `llm_base_url` are set; otherwise `NullLLM`.

Without a usable client the loop stops at `status="no_llm"` (suspects and prior fixes are
retained) and the outcome degrades to a suggestion — no diff is invented.

### 5.3 Attempts and feedback

The loop makes at most `max_fix_attempts` attempts (default **3**); a non-positive value
makes none. Each retry appends the last three feedback messages, such as:

- the model call failed;
- the reply contained no unified diff;
- the diff violated the policy gate (`rule: detail`);
- the diff did not apply (`git apply` message);
- the proof gates failed (`suite_green`, …).

A valid diff is applied to a temporary copy of the checkout with
`git apply --check` followed by `git apply`; the original checkout is never modified. The
prompt carries the ranked suspects together: attempts are per job, not one independent
attempt per suspect.

## 6. Prove: the static policy gate

`janus/core/prove/policy.py::check_policy(diff, *, test_files=(), protected_files=())`
inspects the unified diff text and returns deterministic `PolicyViolation`s. It is
**static**: it runs no test, mutator or coverage tool. `diff_files` and `added_lines` expose
the parsed paths and added lines.

| Rule | Rejects |
|---|---|
| `edits_tests` | any touched path that looks like a test (`test_`, `_test`, `tests/`) or is in the supplied test-file list |
| `edits_protected` | any touched path in `protected_files` (CI workflows, coverage config, …) |
| `weakens_ci` | an added line containing `continue-on-error`, `\|\| true` or `set +e` |
| `skips_tests` | an added skip/xfail marker (pytest, unittest, Jest/Vitest, Go, JUnit) |
| `lowers_threshold` | an added coverage threshold lower than one the diff removes |
| `removes_assertions` | a removed `assert` line without a corresponding added one |
| `weakens_tests` | a diff that deletes more test lines than it adds |

Malformed or empty input yields no violations rather than an exception. Violations are fed
back for a retry and are rendered on the suggest/PR surface; they are **not** persisted in
`gate_results` (that table holds measured gates only).

---

## 7. Prove: the four measured gates

`janus/core/prove/gates.py` defines exactly four gates, always returned in this order by
`evaluate`. The governing rule is **no claim without a gate**: a missing measurement fails
closed (D-074).

| Gate constant | Display name | Passes when |
|---|---|---|
| `GATE_SUITE` | `suite_green` | the patched copy's full-suite command exits ok |
| `GATE_MUTATION` | `mutation_non_regression` | killed mutants **and** the mutant total are both non-decreasing |
| `GATE_COVERAGE` | `coverage_non_regression` | `after >= before - 1e-9` |
| `GATE_TEST_HASHES` | `test_files_unchanged` | the before/after SHA-256 maps of test files are equal |

- The suite gate is a boolean; the full suite runs in the patched copy.
- Mutation testing runs `mutmut` on the files the diff touched, before and after. If either
  measurement is unavailable the gate **fails** with `measured_value="unavailable"`.
- Coverage is measured by the adapter's full-suite coverage command; `coverage_percent`
  counts distinct covered `(file, line)` pairs, so it compares a consistent quantity before
  and after. A missing value on either side fails.
- `test_file_hashes(root)` hashes every `test_*.py` / `*_test.py` under `root/tests` (path
  relative to `root`, POSIX separators). A missing `tests/` directory yields `{}`; an
  unreadable file is skipped. The gate compares the two maps.
- `all_passed` requires **at least one** result and that every result passed; an empty list
  is not a proof.

**Mutation escape hatch.** With `mutation_gate_enabled = false` the processor does not run
`mutmut`; the mutation row is rewritten to `passed=True`, `measured_value="disabled"`,
`baseline_value=None`. It is therefore visibly disabled in the verification table and the
PR body/comment, rather than silently green. This is the only opt-out and it is off by
default (i.e. the gate is enabled).

A proven fix is one where the policy gate produced no violations **and** all four measured
gates passed. Otherwise the best-scoring attempt is returned as `gates_failed` (or
`rejected` when only policy refused every diff).

## 8. Surfaces: suggest and PR

`janus/report/pr.py` renders both surfaces from the same facts and bounds both at
`MAX_PR_BODY_CHARS` (20,000).

- `render_suggest_comment` — diagnosis, ranked suspects, the diff (or "No diff was
  produced."), the verification table, the policy result, and an explicit reason no PR was
  opened. It is used in suggest mode **and** for every failed proof.
- `render_pr_body` — diagnosis, reproduction, change, root cause with suspects, the fenced
  diff, the four-gate verification table and the policy result, plus the guardrail line
  that Janus never merges or force-pushes.
- `render_pr_title` — `Janus fix (CODE_BUG): <file>:<line>`, bounded.
- `branch_name(job_id)` — `janus/fix-<job_id>`; only an integer is interpolated.

**Mode.** `fix_mode` defaults to `suggest`; a repository's `.janus.yml` `mode: pr|suggest`
overrides it. `_effective_mode` accepts only those two values.

- **suggest:** post the comment on the PR when the failing run has one; otherwise post a
  neutral Check run named `"<triage check name>: fix"` with the suggestion as its summary.
  Suggest mode never creates a branch or a PR.
- **pr, proven fix only:** commit the patched temporary checkout to `janus/fix-<job_id>`
  and push a normal branch, then open a **draft** PR via
  `GitHubClient.create_pull_request(..., draft=True)`. No merge, approve, or force-push API
  path exists (D-076). A push/PR failure is logged and **falls back to the suggest
  comment**, so the work is not lost.
- A `no_localization` outcome has no fix surface; the triage Check run/evidence comment is
  the only output.

`janus/github/push.py::commit_and_push` runs `git checkout -B <branch>`, `git add -A`,
`git commit -m <title>`, `git push origin <branch>` with a bounded timeout. The installation
token is supplied as an `http.extraHeader` through `GIT_CONFIG_*` in the child environment
only — never in argv or a remote URL. Errors name the argv and exit code, never the token.
Unsafe branch names are rejected.

## 9. Cost caps and bounds

The loop is bounded at every step:

- at most `max_suspects` (default 5) suspects ranked and fed to the prompt;
- at most `max_fix_attempts` (default 3) generation attempts per job;
- prompt capped at 24,000 characters and per-file source reads bounded;
- at most 3 prior fixes and a bounded diff excerpt per fix;
- LLM timeout `llm_timeout_seconds` (default 60 s) and completion cap `llm_max_tokens`
  (default 4096);
- `git log` bounded to 50 commits, git subprocesses and `git apply` time-bounded.

The orchestrator's outer guardrails remain `max_sandbox_minutes`, `max_llm_tokens` and
`max_fix_retries` in `Settings`; the worker routes an over-cap job to `skipped_budget`.
**Known limit:** the fix loop's own sandbox minutes and LLM token usage are not currently
added to `jobs.cost_minutes` / `jobs.llm_tokens` (those are filled from reproduction and
worker accounting), so the caps bound the loop structurally but do not yet debit its actual
spend. Closing that gap belongs with the Phase 8/benchmark accounting work.

## 10. Persisted data

The fix half of `_persist` runs in the same transaction as the S1 rows.

| Table | Written when | Columns |
|---|---|---|
| `suspects` | localization produced any suspect | `job_id`, `file`, `line`, `score`, `rank`; `introducing_commit` stays `NULL` |
| `fixes` | a diff exists (proven, `gates_failed`, `rejected`, or `error` with a diff) | `job_id`, `suspect_id` (top suspect or `NULL`), `attempt` (number of attempts made), `diff`, `status` |
| `gate_results` | the recorded fix has measured gates | `fix_id`, `gate`, `passed`, `measured_value`, `baseline_value` |

No diff means no `fixes` row (and no `gate_results`); suspects are still recorded when
localization found any. `no_localization` writes nothing. Policy violations and prior fixes
are evidence for the surface and are not stored in these tables.

The fix loop returns one of: `proven`, `no_localization`, `no_llm`, `no_diff`, `rejected`,
`gates_failed`, `error`.

## 11. Acceptance (from `docs/IMPLEMENTATION_PLAN.md` Phases 5–7)

**Phase 5 — Localize + Retrieve + Generate.** On known bugs the suspect list contains the
true `file:line`; bisect identifies the introducing commit; generated diffs apply cleanly
and never touch tests.

- Implemented: SBFL unit tests assert the true faulty line ranks first; generated diffs are
  applied only after `git apply --check` and are rejected by the policy gate if they touch
  tests; retrieval and prompt/extraction have unit tests.
- Deferred: bisect execution, so it does not yet identify the introducing commit.

**Phase 6 — Proof + Policy gates.** Each gate has pass/fail unit tests; policy rejects a
corpus of known-bad diffs; false-fix rate ≈ 0 on the sample set; failed proof after retries
falls back to a comment.

- Implemented: all four gates and the policy rules have unit tests; failed proof always
  falls back to the suggest surface.
- Deferred: the false-fix rate is measured by the Phase 8 benchmark, not in this milestone.

**Phase 7 — PR mode + surfaces.** Suggest mode comments only; `pr` mode opens a PR with the
verification table; assertions that no merge/force-push API path exists.

- Implemented: suggest posts a comment (or a neutral fix Check run); `pr` opens a **draft**
  PR with the verification table; tests assert no force-push and no merge path; push/PR
  failure falls back to the comment.

## 12. Deferred

- **Benchmark harness (Phase 8):** the BugsInPy subset and its metrics table, including the
  false-fix rate.
- **`git bisect`:** the planner/parser exist, but a `--depth 1` checkout has no ancestry, so
  bisect is not run and `introducing_commit` stays `NULL` (D-070).
- **Output-idempotency marker:** duplicate Check runs/comments/PRs on an at-least-once
  retry are still possible (`FUTURE.md` §D).
- **Backend D4–D6:** fairness/rate limits/budgets, failure dedup, observability and the load
  test.
