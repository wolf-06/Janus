# Janus — S0 Spec: GitHub App Spine

Source of truth: `PLAN.md` §1.1 and §5 (S0). This spec is the contract for milestone **S0**,
covering **Phase 0 (scaffold & foundations)** and **Phase 1 (S0 GitHub App spine)**.

The agent must not advance past S0 until every acceptance test below passes and the
manual E2E is demonstrated.

---

## 1. Scope

**In scope (S0):**

- Package scaffold, toolchain, config, structured logging, DB session, Alembic,
  Postgres via `docker-compose`, CI, README.
- GitHub App **manifest flow** (one-click install) and credential persistence.
- Webhook endpoint with **HMAC-SHA256** signature verification.
- Event handling for `workflow_run` (completed + failure) and `check_run`.
- App JWT → **installation token** client (RS256); fetch run logs and the
  **last-green → first-red** diff via the commits/compare API.
- Post a **Check run** proving the webhook → Check path.
- Postgres schema for `installations`, `repositories`, `runs`, `jobs`, `diagnoses`.
- Enqueue a job on a failed run (idempotent on delivery id).

**Non-goals (must NOT start before S0 is demoed):**

- Reproduce (sandbox reruns, profiles) — S1.
- Triage (7 signals, scoring, tau/epsilon) — S1.
- Fix loop (SBFL/bisect, retrieval, LLM diff, proof/policy gates, PR mode) — S2.
- Any deferred item in `PLAN.md` §3.

S0 stops at: **a failing commit produces a real Check run, locally, end to end.**

## 2. Deliverables

### 2.1 Phase 0 — Scaffold & foundations

Ordered tasks:

1. **Repo bootstrap**: commit the plan docs as the initial commit.
2. **`pyproject.toml`**: metadata, `requires-python = ">=3.12"`, runtime + dev deps,
   and tool config `[tool.ruff]`, `[tool.mypy]`, `[tool.pytest.ini_options]`
   (`testpaths = ["tests"]`).
3. **Layout**: the flat `janus/` package tree at the repo root with `__init__.py` in
   every package; stub modules empty until Phase 1.
4. **Hygiene files**: `.gitignore` (`.venv/`, `__pycache__/`, `.env`, caches),
   `.env.example`, `.pre-commit-config.yaml`.
5. **`janus/app/config.py`**: `Settings(BaseSettings)` with `database_url`,
   `log_level`, `github_app_id`, `github_private_key_path`, `github_webhook_secret`,
   `github_client_id`, `github_client_secret`; `env_prefix="JANUS_"`, `env_file=".env"`.
6. **`janus/app/logging.py`**: `configure_logging(level)` → structlog JSON renderer.
7. **`janus/db/session.py`**: `create_engine(settings.database_url)`, `SessionLocal`,
   `get_session()` FastAPI dependency.
8. **`janus/db/models.py`**: `Base(DeclarativeBase)`; tables added in Phase 1.
9. **Alembic**: `alembic init janus/db/migrations`; wire `env.py` to
   `settings.database_url` and `Base.metadata`; `alembic.ini` reads the URL from env
   (not hardcoded).
10. **`janus/app/main.py`**: FastAPI app factory, lifespan (logging + engine), router
    includes, `GET /health` → `{"status": "ok"}`.
11. **`docker-compose.yml`**: `postgres:16` service with healthcheck, volume, env from
    `.env`.
12. **Tests**: `tests/conftest.py`, `tests/unit/test_config.py` (env/prefix parsing),
    `tests/unit/test_health.py` (TestClient `/health` == ok).
13. **CI**: `.github/workflows/ci.yml` — `uv sync`, `ruff check`,
    `ruff format --check`, `mypy janus`, `pytest`.
14. **`README.md`**: quickstart (`uv sync`, `docker compose up -d`,
    `alembic upgrade head`, `uvicorn`), smee.io webhook note, S0 scope + non-goals.

**Gate (Phase 0):** `pytest` passes; `ruff` + `mypy` clean; app boots; `GET /health`
= ok; `alembic upgrade head` creates an empty schema against compose Postgres.

### 2.2 Phase 1 — S0 GitHub App spine

Ordered tasks:

1. **Schema + migration**: tables `installations`, `repositories`, `runs`, `jobs`,
   `diagnoses` (§1.4 fields); one Alembic revision; `alembic upgrade head` clean.
2. **`janus/db/repository.py`**: typed CRUD — upsert installation/repository, insert
   run, create job, set diagnosis; idempotency keyed on `run_id`/delivery id.
3. **`janus/github/webhook_verify.py`**: `verify_signature(secret, body, header)` —
   constant-time HMAC-SHA256 over raw body vs `X-Hub-Signature-256`; returns bool,
   never raises on mismatch.
4. **`janus/github/app_auth.py`**: `app_jwt(settings)` (RS256, ≤10 min) and
   `installation_token(jwt, installation_id)` via httpx; in-memory cache with expiry.
   **Tokens never appear in clone URLs** (`PLAN.md` §4).
5. **`janus/github/client.py`**: installation-token REST client — get workflow run,
   download logs, list commits, compare commits (last-green→first-red), create Check
   run, post issue comment. All HTTP injectable/mockable.
6. **Baseline diff**: resolve last-green run on the branch vs first-red head; compute
   the `compare` diff; store `baseline_sha` on `runs`. Resolves open question §5 Q2
   provisionally as "previous successful run on the branch" (documented in code + this
   spec).
7. **`janus/app/api/webhooks.py`**: `POST /webhooks/github` — read raw body, verify
   HMAC (401 on failure), filter `workflow_run` (completed + failure) and `check_run`,
   map to repo/installation, create `runs` + `jobs`, return 202; idempotent on
   delivery id.
8. **`janus/github/manifest.py` + `janus/app/api/manifest.py`**: `GET /manifest/start`
   (redirect to GitHub manifest creation) and `GET /manifest/callback` (exchange
   `code` → app id / private key / webhook secret), persist credentials, redirect to
   success page.
9. **`janus/report/check_run.py`**: on enqueued failed run, post a Check run
   (`in_progress`) proving the webhook → Check path.
10. **Tests**:
    - `tests/unit/test_webhook_verify.py` — valid signature passes; tampered
      body/signature fails.
    - `tests/unit/test_manifest.py` — callback exchange mocked (`respx`); credentials
      persisted.
    - `tests/unit/test_diff.py` — last-green→first-red compare selects correct
      base/head.
    - `tests/unit/test_check_run.py` — Check-run POST payload mocked (`respx`).
    - `tests/integration/test_webhook_flow.py` — signed payload → run+job persisted →
      Check posted.
11. **E2E (manual, see §4)**: smee.io tunnel → push a failing commit to the seed repo →
    Janus verifies, enqueues, posts a Check run.

**Gate (Phase 1 / S0):** the four unit suites pass; the integration test proves
persist + Check; the manual E2E posts a real Check run on a red build. Matches
`PLAN.md` §5 S0 ("webhook to Check run works end to end, locally").

## 4. Manual E2E checklist (S0 demo)

1. `docker compose up -d postgres` and `uv run alembic upgrade head` succeed.
2. Start the app: `uv run uvicorn janus.app.main:app --reload`.
3. Start a tunnel (smee.io or ngrok) and point the GitHub App webhook URL at
   `POST /webhooks/github` with the configured secret.
4. `GET /manifest/start` completes the manifest install; credentials persist.
5. Push a **failing commit** to the seed repo.
6. Janus receives the HMAC-verified `workflow_run` (completed + failure) event,
   persists a `run` + `job`, and posts an `in_progress` **Check run**.
7. The Check run appears on the real red build.

- [ ] App boots; `/health` ok.
- [ ] Manifest install stores credentials.
- [ ] Webhook accepted (valid HMAC) and rejected on tamper (401).
- [ ] `run` + `job` rows persisted; enqueue idempotent on delivery id.
- [ ] Check run posted and visible on the failing commit.

## 7. Open decisions to confirm before coding

1. Python pin 3.12 vs system 3.14 — **recommend 3.12**.
2. Manifest-callback credential persistence: `.env` write vs OS keyring vs
   DB-encrypted column — **recommend `.env` for S0**, document rotation.
3. Test Postgres: `docker-compose` vs `testcontainers` — **recommend compose** for S0.
4. Baseline definition (`PLAN.md`/open question §5 Q2) — accept the provisional
   "previous successful run on branch".
